# Host Router 管理面板

管理面板为现有 Rust 程序增加 `panel` 子命令。它与 `serve` 转发进程分开运行，通过原有私有 Unix 控制套接字读取状态、事务提交规则。TCP、TLS SNI、HTTP Host、QUIC v1/v2、容量管理和 DDNS 内核没有重写。

从 0.2.0 起提供 amd64 / arm64 静态二进制、完整源码、终端管理入口和面板安装脚本。

## 功能

- 中文响应式仪表盘：规则数量、TCP/QUIC 当前会话、累计流量、累计接入、系统资源和有效 TCP 容量。
- 实时连接趋势：每 5 秒采样，最多保留当前浏览器会话的 60 个点；切换或关闭浏览器后不作为历史监控存储。
- 规则添加、编辑、批量添加、搜索、协议筛选、分页、多选删除；支持备注、精确域名、通配域名、默认目标和 IPv6。
- JSON 配置导出、校验导入。默认端口、DNS 刷新间隔、连接/识别/QUIC 空闲超时、访问日志可在线修改。
- 配置写入前自动备份，最多 30 份；支持下载与恢复。失败的提交也可能保留一份变更前快照。
- 最多 500 条持久化管理操作记录，涵盖登录、配置变更、失败、恢复、密码修改和服务操作；这不是逐连接访问日志。
- 修改管理员密码、退出登录，以及安装器授权的 systemd 内核启动、停止、重启。

与命令行并用时采用配置版本校验：页面读取配置后，如果命令行或其他窗口先改过配置，旧页面的保存会被拒绝，需要刷新。整批配置由原内核检查并绑定新增端口，成功才提交，避免局部生效。

## 构建

使用仓库要求的 Rust 版本，运行：

```bash
cargo build --locked --release
```

前端是内嵌 HTML/CSS/JavaScript，无 CDN、运行时 Node.js 或数据库依赖；修改 `web-panel/` 后需要重新编译 Rust 程序。`web-panel/package.json` 仅用于浏览器测试，不是生产运行依赖。

发布静态二进制仍可用原仓库的 `build.sh`。在已有旧内核的机器上可以只安装新面板二进制，继续连接旧内核的控制套接字。

## 一键安装与菜单

采用 systemd 的 Linux，以 root 运行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YJVIst/host-router/main/install.sh) panel-install
```

交互只需填写三项：管理员用户名、管理员密码、Web 访问端口（默认 18110）。用户名为 3–64 个 ASCII 字母、数字、点、下划线或连字符；密码至少 14 字节，输入时不回显；端口范围 1024–65535。安装器自动发现公网 IPv4，必要时使用本机出口 IPv4。

默认监听 `0.0.0.0:所选端口`，直接由 Rust 提供 HTTP；不安装 Nginx、不申请证书、不修改防火墙。若有云安全组，请放行对应 TCP 端口。HTTP 没有 TLS 加密，可按下一节自行增加 HTTPS。

省略 `panel-install` 打开菜单，选择 **10 可视化管理面板**：

- 安装或重新配置管理员账户、密码、端口。
- 启动、停止、重启独立面板服务。
- 查看访问地址、安装时登录信息，以及 HTTPS 配置文档入口。

再次执行安装会使用本次填写的账号和密码，原登录会话失效；不会删除规则、备份或操作记录。已有内核服务保持运行，面板安装不覆盖内核二进制、不重启内核，不修改其他 agent。没有内核服务时创建并启动空规则内核；内核用户必须为 `hostrouter`，非标准部署需手动接入。

标准路径：

| 内容 | 默认位置 |
| --- | --- |
| 内核程序 | `/usr/local/bin/host-router` |
| 转发配置 | `/etc/host-router/config.json` |
| 面板程序 | `/usr/local/lib/host-router-panel/host-router` |
| 面板数据 | `/var/lib/host-router-panel` |
| 安装恢复备份 | `/var/backups/host-router-panel` |
| 面板服务 | `host-router-panel.service` |

这些路径不依赖开发机器的挂载目录。面板使用专用普通用户 `hostrouter`，sudoers 仅允许三个固定命令：`systemctl start|stop|restart host-router.service`。占用的 Web 端口会在修改面板前拒绝；面板启动失败时尝试恢复上次面板二进制、服务配置和凭据。恢复备份包含账户资料，只供 root 读取。

查看登录信息：

```bash
cat /var/lib/host-router-panel/access.txt
cat /var/lib/host-router-panel/管理员登录信息.txt
```

凭据文件记录最近一次安装/重设时的密码，权限 0600。网页修改密码后不会把新密码再写成明文。

## 从源码安装

先完成上方 Cargo 构建，再以 root 执行：

```bash
bash scripts/install-panel.sh --binary ./target/release/host-router
```

随后同样只填写用户名、密码、端口。安装器在 Debian/Ubuntu、dnf/yum 系统自动补装所需工具；其他发行版需提供 Bash、curl、CA 证书、sudo、util-linux、useradd、iproute2 和 systemd。

非交互部署可使用 `--username USER --password-stdin --port PORT`，将密码经标准输入传递，避免写入命令参数。其他可选参数：

```text
--origin http://203.0.113.10:18110
--config /etc/host-router/config.json
--data-dir /var/lib/host-router-panel
--base-path /console/
```

自定义配置必须与已有内核服务实际使用的配置一致，配置与数据目录应属于 `hostrouter`。安装器不会擅自更改其他用户或系统目录的所有者。普通入口不要求填写域名。

## 可选 HTTPS 反向代理

在具有证书的反向代理环境中，安装时可显式传入 `--origin https://router.example.com`。此时面板只监听回环地址 `127.0.0.1:所选端口`，Cookie 启用 Secure；反向代理、域名解析、证书由管理员自行配置。例：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YJVIst/host-router/main/install.sh) panel-install --origin https://router.example.com
```

在已有 HTTPS Nginx `server` 中配置（示例端口 18110）：

```nginx
location / {
    proxy_pass http://127.0.0.1:18110;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    client_max_body_size 2m;
    proxy_read_timeout 30s;
    proxy_cache off;
}
```

子路径部署可传 `--base-path /console/`，Nginx 使用 `location ^~ /console/`；`proxy_pass` 不加尾部斜杠，以保留完整路径。`--origin` 必须与浏览器实际协议、域名和端口一致，不含路径。

若现有转发内核占用公网 443，反向代理应另选 IP/端口，或通过现有域名分流规则将管理域名转发至本机另一个 HTTPS 监听端口。不要让两个服务争用同一地址端口。

## 手动启动与权限

已有服务、无需安装器时：

```bash
# 配置文件/目录应属于运行内核的同一服务用户，或由 root 运行本地管理进程。
# 默认数据目录需先由管理员创建并交给该服务用户。
host-router -c /etc/host-router/config.json panel \
  --data-dir /var/lib/host-router-panel \
  --origin https://router.example.com
```

不加 `--manage-service` 时面板不提供 systemd 启停权限。此模式可以配置 `NoNewPrivileges=yes`；安装器的服务模式需要 sudo 完成固定动作，不能打开该选项。面板不提供终端、Shell 或任意命令执行 API。

内核停止时，规则和备份仍可查看；必须明确勾选离线保存，方可写配置。离线写入会检查内核文件锁和套接字，不自动绕过仍在运行的内核。下一次启动内核后离线配置生效。

资源连接上限等不能由内核热修改的字段不放在普通设置表单中。若通过 JSON 导入调整，应停止内核、明确离线导入后再启动；在线导入会被内核拒绝。

## 安全与数据

- PBKDF2-HMAC-SHA256，600,000 次迭代，独立随机盐；安装器使用管理员提供的密码，手动 `panel-init` 可生成 144 位熵随机密码。
- HttpOnly + SameSite=Strict Cookie；HTTPS origin 使用 Secure；会话最长 8 小时，进程重启失效，修改密码使全部会话失效。
- 写操作需要自定义请求头；已登录操作还需会话 CSRF token；存在 Origin 时必须完全匹配配置的 origin。
- 登录全局限制每分钟 20 次，最多 32 个会话，限制请求体大小；不会信任客户端自行提供的转发 IP 头。
- HTML 转义显示用户域名与备注；CSP 禁止内联脚本、外部脚本与页面嵌入。
- 私有目录 0700、凭据/哈希/备份/操作记录文件 0600；持久化写入使用同目录临时文件加原子替换。
- Cookie、密码和 CSRF token 不写入操作记录。

数据目录内容：`admin.json`（密码哈希）、`管理员登录信息.txt`（初始凭据）、`backups/`（配置快照）、`audit.json`（管理记录）、锁文件。需要备份时按敏感管理员资料保护，不要上传至公开仓库。

遗忘密码时，可通过菜单重新配置面板账户，或者停止面板后以服务用户执行 `panel-account --data-dir /var/lib/host-router-panel --username USER --password-stdin`，经标准输入提交新密码，再启动面板。此离线命令通过运行锁拒绝覆盖正在使用的账户，现有规则和备份不受影响。

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --locked --release
python3 tests/panel.py target/release/host-router
# root + mount/PID namespace：真实文件安装、终端输入、HTTP 登录、回滚；仅模拟 systemctl

# 原内核的真实 TCP/TLS/QUIC 检查（需要 aioquic、dnslib）

```

可设置 `TMPDIR` 指向空间充足的目录；`HOST_ROUTER_BIN` 指定浏览器测试二进制；`HOST_ROUTER_SCREENSHOTS` 指定截图目录。测试凭据位于各自临时目录，不是验收环境管理员账户。

## 本机管理 API

所有路径相对于 `--base-path`。使用 Cookie 会话；登录后 `/api/me` 返回 `csrf`，后续写操作同时发送 `X-Requested-With: host-router-panel` 与 `X-CSRF-Token`。API 不接受任意文件路径、系统服务名或 Shell 命令。

| 方法与路径 | 用途 |
| --- | --- |
| `POST api/login` | `{username,password}` 登录 |
| `GET api/me` | 当前会话、CSRF、功能开关 |
| `POST api/logout` | 撤销当前会话 |
| `POST api/password` | `{current,password}` 修改密码并撤销全部会话 |
| `GET api/status` | 内核可达状态及原内核指标 |
| `GET api/config` | 完整配置与 `revision` |
| `PUT api/config` | `{config,revision,offline:false}` 事务应用配置 |
| `POST api/validate` | 验证完整配置，返回规则数与监听地址数 |
| `GET api/backups` | 最近配置快照列表 |
| `GET api/backups/{id}` | 下载对应配置 |
| `POST api/backups/{id}` | `{revision,offline:false}` 恢复对应配置 |
| `GET api/audit` | 管理操作记录，最新在前 |
| `POST api/service/{action}` | `start`、`stop`、`restart`；需启用服务控制 |

内核无法连接时状态接口返回 `running:false`；此时不会展示伪造的在线指标。过期配置版本返回 HTTP 409，未登录返回 401，CSRF/Origin 不符返回 403，登录限速返回 429。规则错误由原内核校验并保留原配置；字段解析错误可能返回 Axum 的 400/422，前端显示失败而不误报成功。


## Rust Web 端口直接访问

需要不经过 Nginx 的直接 HTTP 管理时，可以显式启动：

```bash
host-router -c /etc/host-router/config.json panel \
  --listen 0.0.0.0:18110 \
  --origin http://203.0.113.10:18110 \
  --allow-public-http \
  --data-dir /var/lib/host-router-panel
```

将示例 IP 改为实际访问地址；该模式直接由 Rust 提供 HTTP，没有 TLS 加密。Cookie 仍为 HttpOnly、SameSite=Strict；CSRF、Origin 校验、密码哈希、登录限速保持启用。默认启动行为仍仅允许回环监听。

接入已有生产内核时，只安装独立面板二进制和服务，使其以现有内核用户读取同一配置与套接字即可。无需复制规则到新内核或重启现有转发进程。选择空闲 Web 端口，保留其他 agent 的服务、文件与防火墙规则。

### 后端地址与端口

单条新增/编辑表单将“后端地址”和“后端端口”分开填写。地址可为 IPv4、IPv6 或域名，端口为 1–65535。IPv6 可直接填写 `2001:db8::10`；面板提交时自动组装为内核已有的 `[2001:db8::10]:8443` 格式。旧规则打开时自动拆分，不改变存储格式；未修改这两个字段时保留原目标字符串，包括依赖默认端口的旧规则。

### TCP 异常累计的含义

总览的“TCP 异常累计”可打开九种内核计数分类。它是当前内核进程从启动开始的累计计数，不是当前失败率，也不等于后端故障数。其中“握手阶段结束或被拒绝”包括识别域名前的连接关闭、读取错误和报文校验错误；“转发阶段读写异常”也可能包括正常业务中的对端主动重置。

这些计数没有记录每次失败的源 IP、域名和底层错误，不能据此断言攻击、后端故障或某个客户端有问题。当前内核的访问日志开关记录成功选择目标的转发事件，不会补齐这些失败的子原因。排障时应结合短期增量、服务日志与实际转发探测，而不应为清零计数重启生产内核。
